# AWS Investigation Commands

All commands are read-only. Replace `<placeholders>`. Add `--region <region>` (and `--profile <profile>` if used) to every call.

## Gotchas (read first)

- **Region scoping is silent.** A resource in another region simply does not appear. If something "doesn't exist", check the region before anything else.
- **Two different timestamp units.** `logs start-query` takes epoch **seconds**; `logs filter-log-events` takes epoch **milliseconds**.
- **Logs Insights is async.** `start-query` returns a `queryId`; poll `get-query-results` until `status` is `Complete`.
- **Missing datapoints are not zero.** `get-metric-statistics` omits periods with no data. An empty result can mean "no traffic" or "not emitting".
- **ALB 5xx has two sources.** `HTTPCode_ELB_5XX_Count` is generated by the load balancer (no healthy targets, timeouts). `HTTPCode_Target_5XX_Count` is returned by your app. They point to different root causes.
- **SQS counts are approximate** and eventually consistent. Sample twice a minute apart before drawing conclusions.

Time helpers (GNU date; on macOS use `date -v-2H +%s`):

```bash
START=$(date -d '2 hours ago' +%s); END=$(date +%s)
START_ISO=$(date -u -d '2 hours ago' +%Y-%m-%dT%H:%M:%SZ); END_ISO=$(date -u +%Y-%m-%dT%H:%M:%SZ)
```

## Change correlation

```bash
# Write (non-read-only) control-plane events in the window
aws cloudtrail lookup-events --start-time "$START_ISO" --end-time "$END_ISO" \
  --lookup-attributes AttributeKey=ReadOnly,AttributeValue=false --max-results 50 \
  --query 'Events[].{time:EventTime,event:EventName,user:Username,source:EventSource}' --output table

# Recent pipeline executions
aws codepipeline list-pipeline-executions --pipeline-name <pipeline> --max-items 5 \
  --query 'pipelineExecutionSummaries[].{id:pipelineExecutionId,status:status,start:startTime}' --output table

# Lambda: when was the function last changed
aws lambda get-function-configuration --function-name <fn> \
  --query '{state:State,lastUpdate:LastUpdateStatus,modified:LastModified,version:Version}'
```

## Alarms and service health

```bash
# Alarms currently firing
aws cloudwatch describe-alarms --state-value ALARM \
  --query 'MetricAlarms[].{name:AlarmName,metric:MetricName,reason:StateReason}' --output table

# AWS-side incidents (requires Business/Enterprise support; endpoint is us-east-1)
aws health describe-events --region us-east-1 --filter eventStatusCodes=open
```

## Logs (CloudWatch Logs Insights)

```bash
QID=$(aws logs start-query --log-group-name <log-group> \
  --start-time $START --end-time $END \
  --query-string 'fields @timestamp, @message
    | filter @message like /(?i)(error|exception|timeout)/
    | stats count() as hits by bin(5m)
    | sort @timestamp asc' \
  --query queryId --output text)
aws logs get-query-results --query-id "$QID"
```

Useful query strings:

```
# Top error messages
fields @message | filter @message like /(?i)error/ | stats count() as c by @message | sort c desc | limit 20

# Lambda: slowest invocations and cold starts
filter @type = "REPORT" | stats max(@duration), avg(@duration), count(@initDuration) as coldStarts by bin(5m)

# Lambda: timeouts
filter @message like /Task timed out/ | stats count() by bin(5m)
```

Quick grep without Insights (milliseconds):

```bash
aws logs filter-log-events --log-group-name <log-group> \
  --start-time $((START*1000)) --filter-pattern '"ERROR"' --max-items 50
```

## Metrics

```bash
aws cloudwatch get-metric-statistics --namespace <ns> --metric-name <metric> \
  --dimensions Name=<dim>,Value=<value> \
  --start-time "$START_ISO" --end-time "$END_ISO" --period 300 --statistics Sum
```

| Component | Namespace | Metrics | Dimension |
|---|---|---|---|
| ALB | `AWS/ApplicationELB` | `HTTPCode_ELB_5XX_Count`, `HTTPCode_Target_5XX_Count`, `TargetResponseTime`, `UnHealthyHostCount` | `LoadBalancer=app/<name>/<id>` |
| API Gateway | `AWS/ApiGateway` | `5XXError`, `4XXError`, `Latency`, `IntegrationLatency` | `ApiName=<name>` |
| Lambda | `AWS/Lambda` | `Errors`, `Throttles`, `Duration`, `ConcurrentExecutions` | `FunctionName=<fn>` |
| SQS | `AWS/SQS` | `ApproximateAgeOfOldestMessage`, `ApproximateNumberOfMessagesVisible` | `QueueName=<queue>` |
| RDS | `AWS/RDS` | `CPUUtilization`, `DatabaseConnections`, `FreeableMemory`, `ReadLatency`, `WriteLatency` | `DBInstanceIdentifier=<id>` |
| DynamoDB | `AWS/DynamoDB` | `ThrottledRequests`, `ReadThrottleEvents`, `WriteThrottleEvents`, `SystemErrors` | `TableName=<table>` |
| ECS | `AWS/ECS` | `CPUUtilization`, `MemoryUtilization` | `ClusterName`, `ServiceName` |

## Compute

```bash
# Load balancer target health (why is the LB returning 502/503?)
aws elbv2 describe-target-health --target-group-arn <tg-arn> \
  --query 'TargetHealthDescriptions[].{target:Target.Id,state:TargetHealth.State,reason:TargetHealth.Reason}' --output table

# ECS service: desired vs running, recent events
aws ecs describe-services --cluster <cluster> --services <service> \
  --query 'services[].{desired:desiredCount,running:runningCount,pending:pendingCount,events:events[:5].message}'

# ECS: why did tasks stop (OOM, failed health check, image pull)
aws ecs list-tasks --cluster <cluster> --service-name <service> --desired-status STOPPED
aws ecs describe-tasks --cluster <cluster> --tasks <task-arn> \
  --query 'tasks[].{stopped:stoppedReason,containers:containers[].{name:name,exit:exitCode,reason:reason}}'

# EC2 instance and system status checks
aws ec2 describe-instance-status --include-all-instances \
  --query 'InstanceStatuses[].{id:InstanceId,state:InstanceState.Name,system:SystemStatus.Status,instance:InstanceStatus.Status}' --output table

# EKS: cluster state, then use kubernetes-commands.md
aws eks describe-cluster --name <cluster> --query 'cluster.{status:status,version:version}'
aws eks update-kubeconfig --name <cluster>
```

## Data stores

```bash
aws rds describe-db-instances \
  --query 'DBInstances[].{id:DBInstanceIdentifier,status:DBInstanceStatus,class:DBInstanceClass,multiAZ:MultiAZ}' --output table

# Failovers, reboots, storage-full, maintenance in the last 24h (duration in minutes)
aws rds describe-events --source-type db-instance --duration 1440 \
  --query 'Events[].{time:Date,source:SourceIdentifier,msg:Message}' --output table

aws dynamodb describe-table --table-name <table> \
  --query 'Table.{status:TableStatus,billing:BillingModeSummary.BillingMode}'
```

## Messaging

```bash
# Queue depth, in-flight, and redrive (DLQ) config
aws sqs get-queue-attributes --queue-url <queue-url> --attribute-names All \
  --query 'Attributes.{visible:ApproximateNumberOfMessages,inFlight:ApproximateNumberOfMessagesNotVisible,redrive:RedrivePolicy}'

# Peek at a DLQ without deleting (messages reappear after the visibility timeout)
aws sqs receive-message --queue-url <dlq-url> --max-number-of-messages 5 \
  --visibility-timeout 0 --attribute-names All --message-attribute-names All
```
